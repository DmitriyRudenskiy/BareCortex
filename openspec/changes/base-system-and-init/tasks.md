## 3. `base.lock`

- [x] 3.1 Define the `base.lock` format: name, version, source URL, checksum, upstream remote, revision, patch series. **This change owns the format; `build-orchestration 2.1` owns the derived contents** — one file, one truth, and the format has to accommodate entries other changes add
  - **Entry:** the format is the entry shape `scripts/build/derive-base-lock.py` writes and `check-base-lock.py` enforces, and the fields a class requires live in `class-map.toml`'s `requires` — 3.7's placement, so the format is one list and not a sentence repeated in three files. A `[[package]]` is `name`, `version`, `url`, `remote`, `revision`, `md5`, `class`, `pages`, and `patches` when it has a series; `[[patch]]` is `file`, `url`, `remote`, `md5`, `description`, `package`, `pages`; `[[unattributed-download]]` is an archive the book lists and no page names, recorded rather than dropped.
  - **Checksums are MD5, and the file says so in its header.** The request for a checksum field and the book's table disagree with the spec's "SHA-256", and the honest resolution is the checksum the source publishes plus a line in the artifact saying which it is — not a field named for an algorithm nobody verified.
  - **`remote` and `revision` are read off the published URL, never looked up behind it.** `remote` is that URL's origin; `revision` is the release tag the URL carries (`v2.6.4` for Flex, `R_2_7_4` for Expat, 13 of 88 packages carry one) or the version where the URL carries no tag. The book publishes no revision field, so a commit hash here would be invented; the derivation records the identifier the URL itself asserts, and the header states that provenance so a reviewer knows what the field is evidence of.
  - **The patch series is attributed by the book's own naming**, `<package>-<version>-<what>.patch`, and cross-checked against the pages that apply it: 5 patches → Bzip2, Coreutils, Expect, Glibc, Kbd. Attribution by page alone is wrong and was wrong first — `glibc-fhs-1.patch` is applied from `chapter08/glibc.html`, which also installs the time zone data, and page-sharing does not make it a tzdata patch.
- [x] 3.2 Consume the file derived by `build-orchestration 2.1` and verify it covers every package in the base set — this task does not retype the book's package list, and a second copy of it is the defect this line exists to prevent
  - **Entry:** `scripts/build/check-base-lock.py --coverage` asks the pinned edition's own index — a page whose link text reads like `Acl-2.3.2` is a page the book builds a package on — and reports `coverage: pages=110 cited=110 uncovered=0`, plus a failure for any entry citing a page that builds nothing. No list of packages exists in this repository to be wrong.
  - **It earned its keep while being written.** It reported `chapter05/gcc-libstdc++.html` built by the book and named by no entry: the derivation's page-name pattern had no `+`, so the page was invisible to it, and its body says only `cd build` while its index text (`Libstdc++ from GCC-15.2.0`) is the book's idiom for "this page builds that other package's archive". Both were fixed in the derivation. A page a tool cannot see is a page it cannot account for, which is the entire argument for asking the book instead of keeping a list.
  - **Offline by default:** the check without `--coverage` validates the file and the map with no network, so it belongs in a gate; `--coverage` is the one command that reaches the edition.

## 5. Systemd link scan

- [x] 5.1 Implement the scan over the image for `libsystemd`, `libelogind`, `pam_systemd`, `libnss_systemd`, failing with the binary and library named
  - **Entry:** `scripts/build/check-no-systemd.py --root <image>`. It reads the **dynamic section** of every ELF file (`readelf -d`, `DT_NEEDED` only) plus `etc/pam.d/*` and `etc/nsswitch.conf`, because those are the three ways a library gets resolved at runtime and PAM and NSS resolve by name in a config file no ELF header mentions. It refuses to run without `--root`: scanning the source tree would produce a pass about binaries it never read. A file with ELF magic that `readelf` cannot read is a failure, not a skip.
  - **Matched by prefix, not equality:** Debian's `systemctl` and `systemd-udevd` resolve `libsystemd-shared-257.so`, and `libsystemd-shared` is the exact library the pinned edition's `-D link-udev-shared=false` exists to keep out. Matching whole sonames would match a distro's suffix and miss the family.
  - **Validated against a real systemd host, which is the negative control:** the Debian guest's `/usr/bin` gives `binaries=557 findings=8` naming `libsystemd.so.0`, and `/usr/lib/systemd` gives 64 findings across 63 binaries. Before the prefix fix the same scan reported 0 findings there — a scan that passes on a systemd host is the failure mode this requirement is about. `python3 test_check_no_systemd.py` covers the parser, the config scan, and the refusal; running it against the finished image is 5.2.
