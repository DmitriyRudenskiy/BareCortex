## Context

The build tree is aligned slot-for-slot with the build-rootfs reference (see
`openspec/changes/align-build-with-build-rootfs`), and `scripts/build/README.md`
already carries one `## <relative-path>` section per file — enforced by
`check_readme_documents_every_file`. What that check does not enforce is the
content: the README's prose (phase table, check list, refusal list) is
hand-maintained beside data that already has a source of record
(`phases.toml`, the check functions' docstrings, `base.lock`). The reference
project's README is its scripts' own documentation; this change makes ours the
same kind of object. See proposal.md for the motivation.

## Goals / Non-Goals

**Goals:**

- The README is regenerable from the repository: scripts' documentation blocks
  + `phases.toml` + check docstrings.
- A check in `tests/test-all.sh` fails on any drift and names the fix.
- The README keeps its current information content (nothing is lost in the
  move).

**Non-Goals:**

- No changes to build behavior, phases, or check logic.
- No documentation for files outside `scripts/build/` (the repo's `README.md`
  and `docs/` are a different concern and keep their current maintenance).
- No i18n, no HTML, no new dependencies.

## Decisions

**D1 — Documentation blocks are marker-delimited comment regions, one per
file.** Each of the five files carries exactly one region:

```
# >>> docs
...markdown text, one `# ` (or `#`) prefix per line...
# <<< docs
```

`derive_readme()` strips one leading `#`/`# ` per line and assembles the
README. Markers instead of "the whole header comment": the polyglot files have
polyglot mechanics (`'''exec'...` lines, shebangs) that a header-scanning
parser would have to special-case, and the markers make the documented region
explicit at the cost of two comment lines. Alternative considered: generating
sections from `argparse --help` output — rejected, argparse formatting is not
documentation and would make the README hostage to CLI refactors.

**D2 — Data comes from its source of record, not from the blocks.** The phase
table is read from `phases.toml` (name, chapter, checkpoint; page counts from
the page lists); the trust-check list is read from the `TRUST_CHECKS` tuple
and each function's `__doc__`. The blocks therefore do not repeat the table or
the list — they carry only prose. Consequence: the check functions' docstrings
become README-facing text and are written in one-line form at the move.

**D3 — `derive-readme` is a subcommand of `build-rootfs.sh`, and it loads
`tests/test-all.sh` lazily.** The check functions live in `test-all.sh`, so
the derivation must read their docstrings from there. `test-all.sh` already
imports `build-rootfs.sh` (as the module `build`) at its top; a module-level
import back would be a cycle, so `derive_readme()` imports `test-all.sh`
inside the function body, only when the subcommand runs. The normal build
path never touches it.

**D4 — The check is byte-for-byte, and it replaces
`check_readme_documents_every_file`.** `check_readme_is_the_scripts` computes
the expected README with the same `derive_readme()` function (no file written)
and compares. Section-name coverage is a strict weakening of equality, so the
old check is deleted, not kept alongside. The generated file carries a
two-line header: `generated by scripts/build/build-rootfs.sh derive-readme.
Do not edit: ...` — the same status as `base.lock` and
`test-expectations.toml`.

## Risks / Trade-offs

- [Markdown in shell comments is ugly — tables and fences need a `# ` prefix
  on every line] → the derivation strips exactly one prefix; the README (the
  file people read) is clean Markdown, the source (comments nobody reads)
  pays the cost. Same trade the reference makes with its script headers.
- [Docstrings become load-bearing README text] → the byte-for-byte check makes
  a docstring edit a visible, fixable event (`derive-readme`), not silent
  drift; one-line docstrings are enforced by convention at the move.
- [Lazy import of `test-all.sh` means a broken `test-all.sh` breaks
  `derive-readme` but not the build] → acceptable: `test-all.sh` is checked
  by itself in the same suite, and a broken test file is already a build-tree
  failure.

## Migration Plan

1. Move the README's prose into the marked blocks; write the check
   docstrings in one-line form.
2. Implement `derive_readme()` + the subcommand; regenerate the README.
3. Replace the check in `test-all.sh`; run the full suite.

Rollback: revert the commit — the README's previous hand-written content is
in git history; nothing downstream depends on the README's bytes.
